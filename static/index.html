WSL2 & Container Virtualization

Windows Subsystem for Linux (WSL2) runs inside a utility VM (the vmmemWSL or vmmem process). It grows with workload; reclaim requires shutting down WSL or closing the owning workload.

Docker Desktop is keeping WSL active

Docker Desktop maintains an active connection to WSL and will restart the VM promptly after shutdown. Quit Docker Desktop first, then try again.

WSL Configuration

To cap WSL2 memory, create .wslconfig in your user profile folder (%UserProfile%\.wslconfig) with: 

[wsl2]
memory=4GB
[wsl2]
memory=4GB

On current Windows builds, WSL Settings also exposes memory options. Prefer Settings when available. See wsl-config docs.
